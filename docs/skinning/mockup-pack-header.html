Pack — header tidy-up

The Pack header is one right_to_left row holding five pads and three checkboxes: Export Zip, Save Package Files, Bulk Tag, Scan Volumes, Apply Modifiers, then Album / Gzip / Optimize. It fills the row at a comfortable window width and collides with the folder name below it. Six treatments follow, all built from chrome the skin engine already has — pads, the amber latch, silkscreen keylines, the rubber deck, LEDs.

Two ideas recur. Latching mini pads replace checkbox prose: “Gzip to .vgz on export” becomes a lit VGZ pad (tooltip keeps the sentence) — the engine's “lit = on” rule, and a huge width win. And batch vs. export are different verbs: batch ops edit the folder in place, export produces the deliverable — they should read as separate clusters, not one queue.

T0 · Today (the problem)

One unbroken row. The three checkbox sentences alone are ~340pt; at any narrower width the row runs left over the folder name and clips. Nothing groups: “Album” modifies Apply Modifiers but sits nearer to Gzip, and Save/Export (outputs) interleave with Scan/Apply (edits).

V1 · Silkscreen tool groups (two-deck header)

Group, don't hide. The header becomes two rows: a title row (folder, unsaved dot, a readiness LED) and a tool row of three engraved silkscreen groups — LEVELS, TAGS, OUTPUT — exactly how a fascia labels its control clusters. The checkboxes become latching mini pads inside their group (ALBUM next to the buttons it modifies, VGZ/OPT beside Export). Everything stays one click away.

engraved keyline + cut-in caption = new silkscreen primitive · minis = bevel::toggle as-is · LED = meter_low/mid/high · cheapest to build

V2 · Two menus (Batch ▾ / Export split button)

Consolidate ruthlessly. The header keeps exactly two controls: a Batch ▾ menu pad and a split Export button — the wide cell fires Export Zip directly, the caret cell opens Save Package Files and the export options. Batch ops cost one extra click, which is honest about frequency: Scan/Apply/Bulk Tag run a few times per pack, Export runs last. Scales for free as batch ops grow (loop-detect, rerips…) without widening the header.

menu = egui popup restyled as a raised plate panel · split pad = two bevel::button_sized cells sharing a border · ticks reuse the CP437 √

V3 · Output deck (export moves to a footer bar)

V4 · Pipeline strip (tag → level → ship)

The header teaches the workflow. One full-width strip of three stages read left to right like a signal chain, each wearing a status LED in its silkscreen caption: TAG is green (GD3 checks pass), LEVEL is amber (scanned, modifiers not applied), SHIP is amber (warnings outstanding). Strongest for first-time pack builders; but it is the widest option, and the LEDs restate what the checklist below already says — status lives in two places.

stage = the V1 group + an LED in the caption · LED state maps from readiness_items() buckets · widest; wraps like V1 when narrow

V5 · Icon pads + options popover (maximum density)

One row, kept honest with captions. Batch ops shrink to icon pads with tiny silkscreen captions beneath — the hardware answer to “icons alone are unguessable”. A gear pad opens the options popover (Album / VGZ / OPT), leaving the two output pads as the only text buttons. Densest single-row layout; the line-icon set already exists. Risk: four icons to learn, and the captions push the header a few points taller anyway.

icon pads = bevel icon buttons + an 8px caption row · popover = the V2 menu panel · gear collects every option in one place

R · Recommended blend (V1 groups + V2's export split)

Groups for the verbs you repeat, a menu for the options you set once. The V1 two-deck header, but OUTPUT collapses to Save Files + the split Export button: gzip/optimize are per-pack decisions made once, so they belong in the caret menu, not on permanent minis. ALBUM stays a lit mini because it changes what Apply does. This is the least chrome that fixes both problems — grouping and width — and every piece already exists in the engine except the silkscreen caption box.

build order: silkscreen group primitive → move checkboxes → split button + menu · the readiness LED can land later without moving anything
