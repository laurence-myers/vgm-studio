Core picker — accuracy vs speed

Five treatments for the Settings Output tab, replacing or enhancing the plain dropdowns now that a chip can carry four cores spanning three orders of magnitude in cost. All examples use the OPL2 slot (the richest row: four cores after the 2026-08 additions) and the app's own chrome. Data shown is illustrative; the "where the numbers come from" section at the end says what would feed it for real.

The accuracy axis is a provenance ladder, not a percentage: a die simulation outranks a cycle model outranks a behavioural one, and hardware is its own row. A clone chip (CQM) is accurate to the clone — flavour, not error — so it carries its own badge rather than a lower rung.

Treatment A — badged dropdown (smallest change)

The dropdown stays; every row gains a tier badge and a speed readout, and the closed state carries the badge so the trade-off is visible without opening anything. No layout change to the Output tab.

Treatment B — the ladder (replace the dropdown with an inline list)

The row expands into an always-visible radio ladder sorted most authentic first, each core carrying two LED meters in the app's segment style: ACC (violet, the provenance rung) and SPD (green, log-scale headroom over realtime; red when below 1×). One glance, no click.

Treatment C — dropdown + spec card

The dropdown stays exactly as-is; selecting a core reveals a spec card beneath with the two meters, the provenance line, licence and upstream — the About-box facts, brought to the moment of choosing.

Treatment D — the map (accuracy × speed, one glance)

Every core for the slot plotted: speed across (log scale, the dashed red line is 1× realtime), authenticity up. Click a pip to choose. The empty top-right corner is honest: nothing is both a die and fast — that corner is what the picker exists to trade about.

Treatment E — a preference, not a picker

Most users want a policy, not a per-chip choice: Fidelity picks each chip's most authentic core that can hold realtime (die sims only when the machine measures fast enough), Performance picks the fastest, Balanced the default table. The per-chip pickers move behind an "advanced" fold and override the policy where set.

Where the numbers come from

Accuracy is registry metadata, not measurement: a CoreInfo::tier enum (HardwareBoard · DieSim · CycleModel · Behavioural) plus a flavour marker for the clone/compat rows — all facts the PROVENANCE table already states in prose. The parity harness's lvl column can annotate a tier ("0.9848 median vs the die") where it has been run, but the ladder itself is provenance.

Speed is measured, once per machine: a short background render of a reference register stream through each core at first launch (or on demand — "measure this machine"), cached in the config as ×realtime. That number is what turns "below realtime" from a label into the red segment, the map position, and the fidelity policy's promotion rule — including the day the blistering-fast CPU arrives.
