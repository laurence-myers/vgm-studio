# RetroWave over Web Serial — investigation (wt-9)

Low-priority investigation into driving the RetroWave OPL3 board from the browser
over **Web Serial** (not WebUSB — the CDC interface is OS-driver-owned). It ends
with a go/no-go, recorded in [`../PLAN.md`](../PLAN.md) (wt-9): **GO, deferred to a
follow-up design** for a worker-hosted batched pump.

## What's here

- **`serial-hardware-spike.html`** — a no-build, no-Rust page that `requestPort()`s
  with the board's USB filter (04D8:E966), opens the CDC port, and replays a
  bring-up + C-major chord + key-off. The wire bytes are **not** re-derived in JS;
  they are generated by the real protocol code and pasted in, so a framing mistake
  cannot creep in:

  ```
  cargo run -p vgms-retrowave --example dump_wire
  ```

  The board is write-only, so it is **verified by listening**. Run it on a machine
  with the hardware attached, over a secure context (https or http://localhost),
  in Chromium. Regenerate the embedded hex if the protocol changes.

- **`serial-timing-rehearsal.html`** — runs the native pump's absolute-deadline
  accumulator (64-frame ≈1.287 ms quanta, 250 ms `MAX_LAG` tolerance) in a Worker
  against a mock writer, and measures two pumps: the naive one-wake-per-quantum
  loop, and a batched render-to-deadline loop on a coarse timer. Open it (or drive
  it headless — it exposes `window.__vgms_timing_result`).

## Measured (headless Chromium, 4000 quanta ≈ 5.1 s)

| pump | mean lag | p99 | worst | deadline resets | verdict |
|------|---------:|----:|------:|----------------:|---------|
| naive (1 wake/quantum) | 128 ms | 252 ms | 301 ms | 49 | **breaches** 250 ms |
| batched (render-to-deadline, 8 ms timer) | 0.66 ms | 1.28 ms | 7.7 ms | 0 | **within** tolerance |

The takeaway: a browser cannot hold a ~1.3 ms cadence with one `setTimeout` per
quantum (timers clamp), so the follow-up pump must **batch** — render every
quantum whose deadline has passed on each coarse wake. That tracks real time to
the timer granularity, comfortably inside the tolerance the native code grants.

## Open frictions for the follow-up (from the crate map)

- `SerialIo: Send` fights a JS-handle transport (a wasm impl is `!Send`) — the web
  seam is the JS boundary, not the trait.
- `Device::initialise` → `reset_chip` sleeps 200 ms synchronously; a web bring-up
  must make the settle async.
- Background-tab timer throttling bunches writes; bounded by the deadline reset,
  but playback should pause/warn when the tab is hidden.
- WritableStream backpressure is unmeasured without hardware.
